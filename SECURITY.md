# Security

Security vulnerabilities can be filed by going to the security tab.

## Making a Report

We welcome all Security / Vulnerability Reports made in accordance with this policy. When received they will be triaged as necessary and as such you can expect the conversation to begin in relation to the raised report.

Any report made, is the same as a ticket being made. It is to cover "one thing" and "one thing" **only.** "one thing" is exactly one code path, so for a request this will be the the code path of the initiating request and the returned response. This is not inclusive of something related to but in another code path, not part of that request. If this occurs, then an additional report is to be made and then reference each report.

All security / vulnerability reports must include as a minimum, an  introduction, description and suggested fix. Introduction providing a summary and context of what has been found. The description must include the exact setup and steps to reproduce. for example:

- each user, their permissions and the tenancy of those permissions
- The setup of every object created and used as part of the discovery
- Each action taken to reproduce the discovery. As this is an API app. Every singe request. either notate, or provide an example using curl command. Include response.

Also as part of the description, any further detailed / technical notes relevant to the Security / Vulnerability Report. You are **required** to demonstrate the security / vulnerability. Failure to do so turns your "report" into spam, as a report without demonstration is just a waste of the time used to produce it. Not only that, but ours as well.

If deemed appropriate you may include any additional headings as you deem fit.


## AI

AI reports will not be accepted **period.** A report may be submitted that has used AI to assist in its creation and as long as its followed this security policy. AI assistive usage must be disclosed and the human that used the AI assistant has completely confirmed that the report made is **100%** accurate. The report **must not be from a bot account,** but the account of the human whom used the AI.

**If and when any one thing is found that is incorrect/incomplete due to the human failing to confirm the report is 100% accurate. Report triage will cease and the report will be sent back to be fixed. "And.... no we will not tell you why it's incorrect. You the human were required to have checked it in the first place, The AI has saved you time, however we will not accept lower quality because you chose a method to create the report that is more often than not less then sufficient." Failure to correct your report will have it closed.**

Of considerable note. The current AI's available (LLM) may be good at processing large amounts of data. Subsequently when they produce a reply, they also return lots of data. Most of the time this returned data is full of waft, fluff and other useless information. Additionally it's often also disjointed. This **is not acceptable** in a report. If a human being can not clearly follow the report, the report will be rejected and required to be fixed up.
